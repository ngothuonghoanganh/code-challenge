# Problem 5 — Resource CRUD API

A REST API for managing `resources`, built with ExpressJS and TypeScript. Data is
persisted in SQLite through Sequelize ORM, while database schemas are managed
exclusively through migrations.

## Features

- Create, list, retrieve, update, and delete resources.
- Search by `name`, `code`, and `description`.
- Filter by `status`, `type`, `ownerId`, and `parentId`.
- Pagination and sorting for collection endpoints.
- Parent/child resource relationships through `parentId`.
- Extensible JSON data through the `metadata` field.
- Soft delete using `status = DELETED` and `deletedAt`.
- Request validation with `express-validator`.
- Exception code, HTTP status, and error message mapping.
- OpenAPI documentation through Swagger UI.

## Tech stack

- Node.js 22.5+
- TypeScript
- ExpressJS
- Sequelize ORM
- SQLite
- express-validator
- Swagger UI Express
- ESLint

## Installation

From the repository root:

```bash
cd src/problem5
npm install
cp .env.example .env
npm run db:migrate
npm run dev
```

The server runs at `http://localhost:3000` by default.

| --- | --- | --- | --- |

## Resource schema

| Field | Type | Required on create | Description |
| --- | --- | --- | --- |
| `id` | UUID | No | Generated by Sequelize with `DataTypes.UUIDV4` |
| `name` | string | Yes | Resource name, up to 200 characters |
| `code` | string | Yes | Unique code, up to 100 characters |
| `type` | enum | Yes | `FILE`, `IMAGE`, `SERVER`, or `ROOM` |
| `description` | string/null | No | Description, up to 2,000 characters |
| `status` | enum | No | `ACTIVE`, `INACTIVE`, or `DELETED`; defaults to `ACTIVE` |
| `ownerId` | UUID | Yes | Resource owner identifier |
| `parentId` | UUID/null | No | Parent resource identifier |
| `metadata` | JSON object/null | No | Type-specific extensible data |
| `createdBy` | UUID | Yes | Creator identifier |
| `updatedBy` | UUID | No | Last updater; defaults to `createdBy` on creation |
| `createdAt` | datetime | No | Resource creation timestamp |
| `updatedAt` | datetime | No | Last update timestamp |
| `deletedAt` | datetime/null | No | Soft-delete timestamp |

`code` may contain only letters, numbers, dots, underscores, and hyphens.

## Create a resource

```bash
curl -X POST http://localhost:3000/api/v1/resources \
  -H 'Content-Type: application/json' \
  -d '{
    "name": "Primary file storage",
    "code": "file-primary",
    "type": "FILE",
    "description": "Stores uploaded files",
    "ownerId": "11111111-1111-4111-8111-111111111111",
    "metadata": {
      "region": "ap-southeast-1",
      "capacity": 1000
    },
    "createdBy": "22222222-2222-4222-8222-222222222222"
  }'
```

## Listing, filtering, and pagination

```http
GET /api/v1/resources?search=file&type=FILE&status=ACTIVE&ownerId=11111111-1111-4111-8111-111111111111&page=1&pageSize=20&sortBy=createdAt&order=desc
```

| Parameter | Description |
| --- | --- |
| `search` | Search in `name`, `code`, and `description` |
| `q` | Alias for `search` |
| `status` | `ACTIVE`, `INACTIVE`, or `DELETED` |
| `type` | `FILE`, `IMAGE`, `SERVER`, or `ROOM` |
| `ownerId` | Owner UUID |
| `parentId` | Parent resource UUID |
| `page` | Page number, default `1` |
| `pageSize` | Items per page, default `20`, maximum `100` |
| `sortBy` | `createdAt`, `updatedAt`, `name`, `code`, or `type` |
| `order` | `asc` or `desc`, default `desc` |

Deleted resources are excluded by default. To list them explicitly:

```http
GET /api/v1/resources?status=DELETED
```

List response:

```json
{
  "data": [],
  "meta": {
    "page": 1,
    "pageSize": 20,
    "total": 0,
    "totalPages": 0
  }
}
```

## Update a resource

```bash
curl -X PATCH http://localhost:3000/api/v1/resources/RESOURCE_ID \
  -H 'Content-Type: application/json' \
  -d '{
    "name": "Updated resource name",
    "status": "INACTIVE",
    "metadata": { "region": "ap-southeast-1" },
    "updatedBy": "33333333-3333-4333-8333-333333333333"
  }'
```

`id`, `createdBy`, `createdAt`, `updatedAt`, and `deletedAt` cannot be updated
directly through this endpoint. The request must contain at least one valid field.

## Soft delete

```bash
curl -X DELETE http://localhost:3000/api/v1/resources/RESOURCE_ID
```

The API returns `204 No Content`. The record remains in the database and is updated:

```text
status = DELETED
deletedAt = deletion timestamp
```

After soft deletion, the detail and update endpoints return `404`.

## Error response

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Request validation failed",
    "details": [
      {
        "field": "ownerId",
        "message": "ownerId must be a valid UUID"
      }
    ]
  }
}
```

| Exception code | HTTP status | Default message |
| --- | --- | --- |
| `VALIDATION_ERROR` | `400` | `Request validation failed` |
| `INVALID_JSON` | `400` | `Request body must contain valid JSON` |
| `INVALID_PARAMETER` | `400` | `Request parameter is invalid` |
| `RESOURCE_NOT_FOUND` | `404` | `Resource not found` |
| `ROUTE_NOT_FOUND` | `404` | `Route not found` |
| `INTERNAL_SERVER_ERROR` | `500` | `An unexpected error occurred` |
